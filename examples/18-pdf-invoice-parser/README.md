# 18 · PDF Invoice Parser

> Extract the invoice number, dates, totals and line items from a PDF, then check the maths. No AI, no API key.

| Difficulty | Time | Credentials | Nodes used |
|---|---|---|---|
| ⭐⭐ Intermediate | 10 min | None | HTTP Request (file), Extract from File (PDF), Code (regex), Edit Fields, IF |

```
Manual Trigger ─▶ Download Invoice ─▶ Extract PDF Text ─▶ Parse Invoice ─▶ Check Totals ─▶ Looks Valid? ─┬─ true  ─▶ Book Invoice (placeholder)
                  (binary PDF)        (plain text)         (regex → JSON)   (sums, due in)               └─ false ─▶ Needs Review (placeholder)
```

## What you'll learn

- Reading **PDF text** with *Extract from File → Extract From PDF*
- Turning text into **structured JSON** with regular expressions (`match`, `matchAll`)
- **Sanity checks** that catch extraction mistakes (line items = subtotal, subtotal + VAT = total)
- Date maths with Luxon (`daysUntilDue`)
- When to use **regex** and when to use **AI** for document extraction

## Setup

1. Import [`workflow.json`](workflow.json). It downloads [`sample-invoice.pdf`](sample-invoice.pdf) from this repo, a fictional invoice generated by [`make-sample-invoice.py`](make-sample-invoice.py).
2. To process your own invoices, replace **Download Invoice** with where your PDFs come from:
   - **Gmail Trigger** / **Email Trigger (IMAP)** with *Download Attachments* on
   - **Google Drive Trigger** on an "Invoices" folder
   - an n8n **Form** with a file field
3. Adjust the regexes in **Parse Invoice** to your supplier's layout.

## How it works

| Node | What it does |
|---|---|
| **Download Invoice** | HTTP Request, *Response Format: File* → binary `data`. |
| **Extract PDF Text** | Puts the PDF's text into `$json.text`. It only works for PDFs that contain real text, not scanned images (see Troubleshooting). |
| **Parse Invoice** | `find(/Invoice Number:\s*(\S+)/)` for single fields; `text.matchAll(/^(.+?)\s*\|\s*(\d+)…$/gm)` for every line item. |
| **Check Totals** | Two booleans plus `daysUntilDue`. *Include Other Fields* keeps everything parsed so far. |
| **Looks Valid?** | Only "clean" invoices are booked automatically. Anything odd goes to a human. |

## Regex or AI?

| | Regex (this recipe) | AI *Information Extractor* ([recipe 09](../09-ai-support-ticket-triage/)) |
|---|---|---|
| Works for | One or a few **known** layouts | **Any** layout |
| Cost | Free, instant | Per-call cost, slower |
| Accuracy | 100% on the known layout, 0% when it changes | Very good, occasionally wrong |
| Best practice | Keep the **validation checks** either way. They catch both regex and AI mistakes. | |

## Ideas to extend

- Append each invoice to Google Sheets or a Data Table, with line items in a second table.
- Create a reminder: if `daysUntilDue < 7`, post to Slack.
- Fall back to AI: on the *false* branch, send the text to an Information Extractor before asking a human.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `text` is empty | The PDF is a **scanned image**. Use an OCR service (e.g. Mistral OCR, Google Document AI, AWS Textract) or a vision-capable LLM. |
| Fields are `null` | The label text differs (`Invoice No.` vs `Invoice Number:`). Check `$json.text` in **Extract PDF Text** and adjust the regex. |
| Password-protected PDF | Extract PDF Text → *Options → Password*. |
| Numbers like `1.234,56` (European format) | Convert before `Number()`: `.replace('.', '').replace(',', '.')`. |
